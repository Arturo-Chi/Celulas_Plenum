Asincronia y event loop

JavaScript es un lenguaje de un solo hilo (Single Thread) Esa principal ventaja hace que nosotros no tengamos porque preocuparnos por temas como la concurrencia, ya que se trabaja solo una tarea a la vez. JavaScripr es single thread, (sus hermanos simplifican código) por lo tanto no se pueden realizar operaciones largas como el acceso a la red sin que se bloquee el hilo principal. Imaginemos que solictamos datos a una API, puede tardar o no en procesar la solicitud, por lo tanto el resto del código se bloquearía hasta tener un response. Para eso es la asincronía, poder realizar operaciones largas sin hacer bloqueos en el resto del código. conceptos básicos: -- EVENT LOOP EN JavaScript AL ser JS un lenguaje de un solo hilo, el procesamiento se da en los threads, unidades básicas de cada proceso que realiza nuestra máquina. Requests EventLoop Register Callback INTENSIVE OPERATION [FileSystem, Database, Computation] Operation complete EventLoop TriggerCallBack -> JS trabaja con la metodología LIFO - Operaciones de CPU y operaciones de I/O En un procesamiento del código de una operación pueden aparecer. Las de CPU son aquellas que van a pasar el mayor tiempo consumiendo los procesos del CPU. Las de Input/Output son aquellas que van a pasar la mayor parte del tiempo esperando la petición del recurso qhe han solicitado - Operaciones concurrentres y paralelas Concurrentes -> Se refiere a la capacidad de un sistema para gesationas varias tares que progresan simultaneamente, aunque no necesariamente al mismo tiempo, intercalando su ejecucón para mantener un avance constante. Paralelismo -> Implica la ejecución literalmente simultánea de múltiples tareas en el mismo instante de tiempo, generalmente aprovechando múltiples núcleos de procesamiento o hilos. EL concepto de event lopp entra ya que como de decíamos, JS es un lenguaje Singlethread, por usa un modelo de concurrencia basado en un buble de evettos que permite manejar operaciones asíncronas de forma no bloqueante. - Operaciones bloqueantes y no bloqueantes Bloqueantes -> Son operaciones que no devuelven el control a la aplicación hasta que se completa la operación, esto provoca que el hilo de ejecución quede bloqueado en estado de espera durante el tiempo necesario para ejecutar la operación. Se usan comúnmente en contextos donde se requiere que el resultado este disponible inmediatamente, como la lectura de archivos, o solicutdes de red sincrónicas. No Bloqueantes -> Devuelven el control a la aplicación inmediatamente, independientemente de si la operación hya finalizado o no, permitiendo que el programa continué con otras tareas mientras se completa la operación en segundo plano. Son especialmente útiles en entornos donde se requiere de alta concurrencia, como servidores web. En SO una de estas puede intentar leer datos y retornar cuantos bytes se leyeron efectivamente, sin esperar a que todos los datos estén disponibles. - Operaciones síncronas y asíncronas Sincronas - Se ejecutan de manera secuencial, donde cada tarea debe completarse antes de que la siguiente pueda comenzar. Haciendo que el flujo principal del programa se bloquee mientras espera la finalización de una operación. -Asíncronas - Permiten que el programa continué ejecutandose sin esperar la finalización de una tarea. Una vez que se inicia una de estas operaciones, como una solicitud a un API o una operación de lectura de archivo, el control se devielve inmediatamente al flujo principal, permitiendo que otras tareas se ejecuten mientras se espera del resultado.
