1.1 Introducción a la Ingeniería de Requerimientos

Es la rama enfocada en que el desarrollo de software se realice de manera ordenada, sistemática y aplicando la reutilización

¿Por qué se le considera una ingeniería?

Pese a que en muchos casos, los desarrolladores reinventan sus soluciones y tratan a cada proyecto como algo nuevo, se ha buscado usar métodos probados así como elementos ya existentes para evitar empezar desde cero con cada solución

El papel del ingerniero de Software

Un ingeniero de software es aquel encargado de construir el comportamiento y las propiedades del hardware necesarias para su uso específico. Además, de por supuesto, escribir las descripciones necesarias sobre el programa.

  1. Documenta requerimientos funcionales
  2. Modela el Sistema con descripciones abstractas
  3. Verifica que el software cumpla con su diseño
  4. Divide el desarrollo para trabajo en paralelo

Buenas prácticas en la gestión de proyectos

  1. Definir el alcance, en cuanto a Objetico, límites y restricciones
  2. Plan general y cronograma con hitos
  3. Estimación de costos y esfuerzos
  4. Planificar el entorno de trabajo y el equipo humano
  5. Identificación de riesgos y recursos

1.2 Ingeniería de Requerimientos

¿Qué son los requerimientos?

Los requerimientos describen qué debe hacer el sistema y cómo debe comportarse, según las necesidades del usuario.

Se redactan en lenguaje natural y se clasifican en:

  • Funcionales
  • No Funcionales

Principios clave:

Conocer el negocio detrás del sistema: Se busca contribuir al objetivo comercial

Entender el dominio de la aplicación: Delimitar cuál es el sector industrial para el que se está desarrollando

Definir requerimientos funcionales y no funcionales: Funciones y restricciones con las que tiene que cumplir el sistema

Uso de prototipos: Permiten al cliente entender hacia dónde va el sistema dando una visualización de funcionalidad limitada

1.3 Introducción a la Arquitectura de Software

La Arquitectura de Software Es la estructura fundamental de un sistema: cómo se divide en componentes, cómo interactúan y cómo evolucionan.

Su propósito es permitir “el diseño para el cambio”, es decir, que el sistema pueda modificarse sin perder calidad.

Elementos de la Arquitectura

  • Componentes: módulos, bibliotecas y servicios
  • Interfaz: Capa de comunicación entre los clientes
  • Relaciones: Cómo es que los módulos se conectan y colaboran entre sí

Arquitectura de Software vs. Arquitectura del Sistema

La arquitectura del sistema considera todos los componentes de un sistema informático, incluyendo hardware, software, redes y dispositivos de comunicación, con el objetivo de garantizar que todos los elementos trabajen juntos de manera eficiente y armoniosa. En contraste, la arquitectura del software se centra exclusivamente en la estructura y organización del software dentro de ese sistema, definiendo cómo se organizan y comunican sus componentes para cumplir con los requisitos técnicos y comerciales.

La arquitectura del sistema abarca tanto el hardware como el software, así como la infraestructura de red y otros subsistemas interconectados, y se ocupa de aspectos como la escalabilidad, la interoperabilidad y la seguridad del sistema en su conjunto. Por otro lado, la arquitectura del software se enfoca en la modularidad, la separación de preocupaciones, la reutilización de componentes y la facilidad de mantenimiento, elementos clave para garantizar que el software sea escalable, seguro y de alta calidad
